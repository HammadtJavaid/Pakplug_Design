## 1. Overview

**Goal.** Ayesha opens the Profile tab and, in one calm screen, sees who she is (name, email, sessions, saved chargers), which car PakPlug thinks she drives, and every account tool she needs: vehicles, saved chargers, identity, notifications, settings, help, sign out. Managing cars is the heart of the flow, because the car drives everything downstream (connector matching, Recommended stations, the charge planner's kWh → % maths). Adding, editing, making primary and deleting a car must feel as solid as Apple Wallet cards: light, precise, reversible until the last tap, and always confirmed.

The visual language is the same as every other flow: Quiet mesh behind lists, Frost Strong grouped cards, Surface sheets with a 38pt top radius, Liquid Glass chrome (tab bar, nav buttons), SF Pro light type, emerald as the single accent, and every number in a Display style.

**Entry points**
1. Tab bar → Profile (index 4). Root tab, tab bar `Selected=Profile` 966:191.
2. Home top-bar bell → Notifications (02 · Appendix 1 red dot).
3. Book a slot / Choose vehicle → **Add vehicle** → Add vehicle (04, returns `pop(true)` and auto-selects a fitting car).
4. Charge planner → "Add battery size" → Edit vehicle with the battery field focused (05 CH5), and Live / Complete "Add your car's battery size" chip (06).
5. Charge tab → "Your vehicle" → My vehicles (05 CH2).
6. Onboarding → Add vehicle with a `VehicleFormDraft` (01.33–01.36 use the same screen; this flow owns the non-onboarding variant).
7. Identity & verification → **Add a vehicle** → Add vehicle → back (user refreshed).

**Exits**
- Notification row → Bookings tab (`/my-bookings`) for `BOOKING_STATUS_CHANGED` / `BOOKING_EXPIRING`; chat thread for `chat_message`; `CallScreen` for `incoming_call` (logic).
- Saved chargers → `FavoritesScreen` (already designed in 02.20–02.24; not redrawn here).
- Host mode → host dashboard or `HostRegistrationScreen` (host flow, out of scope; the switching state is drawn).
- Sign out / Delete account → Sign in (`/login`, 01.07).
- Add/Edit vehicle → back to whoever pushed it (My vehicles, Book a slot, planner, Identity, onboarding).

**Count.** 14 distinct screens and surfaces (Profile, Wallet sheet, Help sheet, sign-out sequence, Account & settings, Coming-soon sheet, Delete-account alert, Edit profile, My vehicles, Delete-vehicle alert, Add vehicle, Edit vehicle, Notifications, Identity & verification) shown in **64 frames** (08.01–08.61 plus 08.05b, 08.14b and 08.16b added in review; the "b" suffix follows 06's convention so later numbers don't shift).

**Text on the Quiet mesh:** normal text colours (brief). Every card that carries grey text is Frost Strong or Surface, never Frost 68%. Sheets are Surface. No Hero mesh is used in this flow; the only mesh-painted element is the driver's **Avatar Mesh** (§7), which follows the Hero rule in miniature: the `mesh/glow` highlight stays in the top-left quarter and never sits under the initials; initials are `text/onMesh` white, ≥ 22pt, on the deep/mid stops (white below the glow measured 4.7–5.7:1, progress log). `text/secondary` is never placed on a mesh. On tinted fills (`status/availableTint` Verification Banner, `bg/tint` wells) secondary text is ≈4.7:1 (5.3:1 on white × tint luminance); check with `node.screenshot` during the build and switch to `text/primary` if it measures under 4.5:1.

**Sheet / Action anatomy (new composite, §7).** Leading-aligned, one rule for every sheet in this flow: icon well 56×56 (radius 16) at (16, top+24) → Title 2 (22 Medium) at top+96 → Body `text/secondary` 8 below, width 370 → optional summary container (`bg/grouped`, radius md) 16 below → buttons pinned. Info sheets have an `Icon Button` Fill S 979:286 ✕ at (352, top+16) (00-system C3) unless the sheet already has a Cancel button (Help); the Summary sheet has neither ✕ nor grabber. Detents are custom (`.custom` height = H), never full-screen. Sheets are used **only** where there is more than a sentence and two buttons: Wallet (Info), Help & support (Info + hotline block), Coming soon (Info), Charging Summary (Summary rows).

**Confirms are native alerts (design spec §4.1-5, same as 05 F and 07.32).** Every short yes/no confirm in this flow is the `Alert` component 1014:577 centred over `bg/scrim`: Logout (08.09), Active Charging Session (08.10), Could Not End Session (08.12), **Delete Account (08.20)** and **Delete Vehicle (08.32)**. The logic's `DestructiveConfirmSheet` keeps its title/message/labels; only the presentation changes (logic unchanged). Rich confirms stay sheets (06.14 "End charging session?" with its estimate row = `Sheet / Action` Kind=Destructive). Button order follows 07.32: side by side → safe action left, destructive right; stacked (labels too long for ~130pt each) → destructive on top, safe below. Alert weights are whatever the `Alert` component already has (Regular/Medium); never Bold/Semibold (brief).

### 2.3 Motion and haptics (shared tokens; nothing new is invented here)
- From 02 §4.0: `snappy` (response 0.30, damping 0.85), `smooth` (0.45, 1.0), `bouncy` (0.40, 0.70), `fade.quick` 150 ms ease-out, `fade.std` 220 ms ease-out.
- From 01 §2: **M-press** (scale 0.97 + Pressed variant, 100 ms ease-out, release `snappy`), **M-push** (native push ≈350 ms), **M-replace** (cross-dissolve 250 ms), **M-rise** (y +12→0, opacity 0→1, 320 ms ease-out, stagger 40 ms), **M-count** (700 ms ease-out count-up), **M-shake** (3 × ±6pt, 320 ms).
- From 06 §4.0: `roll` (numeric content transition for changing numbers, 220 ms `snappy`).
- **Alert** (system, same as 05 §F / 02.04): scrim `fade.std`; alert scales 1.08 → 1 with opacity 0 → 1, 250 ms ease-out; dismiss = `fade.quick`, opacity only (00-system). VoiceOver focus lands on the alert title; the alert is modal; two-finger Z = the safe button. RM: opacity only.
- **Sheet** (custom detent): rises with `smooth` (≈450 ms), scrim `fade.std`; drops with `smooth`; swipe-down dismiss follows the finger, threshold 30% of the sheet height or velocity > 800 pt/s. RM: cross-fade 220 ms.
- **Loading HUD**: scrim `fade.std` + HUD scale 0.92 → 1 (`smooth`) with opacity 0 → 1, appears only if the call takes > 150 ms (no flash for fast calls) and then stays ≥ 600 ms (00-system); leaves with `fade.quick`. Blocks touches. VoiceOver announces the label once (`.announcement`). RM: fade only.
- **Type in motion:** numbers that change (stats, amounts) use `roll` / M-count on Display styles (SF Pro Light); titles Medium; body Regular; "Emph" styles are Medium; no Bold/Semibold anywhere, including alert buttons.
- **Haptics (app map, applied):** *selection* = switches, connector tiles, segmented control, swipe threshold; *light* = card taps, opening a sheet from a button, Call support; *medium* = destructive commits (Logout, End Session & Logout, Delete Vehicle, Delete Account), the vehicle long-press lift, and Save taps; *rigid* = none in this flow; *success* = saved / added / updated / verified; *warning* = an alert that carries a heavy consequence as it appears (Active Charging Session, Delete Account); *error* = any failure; plain confirms (Logout) and Delete Vehicle (the lift or swipe threshold already played one) present with no extra haptic. Never two haptics within 300 ms. List-row navigation has **no** haptic (native iOS feel).
- **Reduce Motion (RM):** every slide, scale, lift, swipe-spring and morph becomes a `fade.quick` cross-fade; no count-up (final values), no check-draw (static mark), no shimmer (static skeletons at 100%). **Reduce Transparency:** Frost and Glass become Surface + hairline.
- **Toast** (1088:631): rises from 12pt below with opacity 0→1 (`smooth`, 00-system), auto-dismisses after 4 s (1 line) or 6 s (2 lines or any action), swipe down to dismiss; haptic follows tone (Success → success, Error → error, Warning → warning, Neutral → none); posted as a polite VoiceOver announcement without moving focus. RM: fade.

## 9. Edge cases and the defaults chosen (Hammad asleep: decided)

1. **Profile with no Driver role** (host who never onboarded as a driver) → "My vehicles" row hidden (logic); "Driver mode" tap runs the role-switch flow in 01.43. Not drawn here.
2. **Sessions unknown** → "—"; **Charged** is always "—" (logic); stat tiles never show "0" for unknown.
3. **Long names / emails** → name wraps to 2 lines in the header card (card grows); email truncates in the middle ("ayesha.khan…@email.com"); Account card name 1 line + tail truncation.
4. **Long vehicle names** ("Mercedes-Benz EQS 580 4MATIC") → name truncates (tail) before the "Primary" pill, which never truncates; Specs wraps to 2 lines when there are 3–4 plugs ("Type 2, CCS 2, Type 1, CHAdeMO · 60.5 kWh").
5. **Vehicle without a battery size** → Specs shows plugs only ("Type 2, CCS 2"), never "· —"; the planner and Live chips link to Edit vehicle (08.49).
6. **Vehicle without a plate** → no Plate Chip; Account & settings "Number plate" shows "—" (logic) when the primary car has none or there is no vehicle (08.16b). **No phone** → the Phone row shows "—" and no "Verified" pill (logic, 08.16b).
7. **First vehicle** → "Set as primary vehicle" defaults On [P20]; the driver can still turn it off. Saving any vehicle marks the driver verified (logic).
8. **Setting a new primary** → the previous primary loses its pill (server is the source of truth); the list re-sorts with the primary first (5.5-9).
9. **Deleting the primary vehicle** → the alert is the same; afterwards no card shows "Primary" until the driver sets one (we don't guess). Footnote stays. Flag: backend could auto-promote the oldest car.
10. **Deleting the last vehicle** → Empty state (08.35). The driver stays Verified (logic auto-latch never un-verifies); the Identity condition card then shows Not done while the banner says Verified. Default: banner follows `user.verified`, card follows vehicles. Flag for Rayan/Hammad.
11. **Delete vehicle while it is used by an upcoming booking** → not in the logic; we don't block. Flag: backend should reject or warn ("This car is on your booking for today").
12. **Battery input** → decimal pad; "60,5" and "60.5" both accepted; 0 or > 1000 → error on submit (logic); empty is fine (optional).
13. **Plate input** → uppercased live (logic); spaces kept as typed; max 10 characters.
14. **Phone validation** → 11 digits starting "03" (hint "03XXXXXXXXX"); spaces ignored; "+92" normalisation is [P16] flag-only.
15. **Push toggle with iOS permission denied** → the switch turns on but iOS won't deliver; [P28] flag-only alert. Default tonight: no extra UI.
16. **Apple relay email** → detected by the `privaterelay.appleid.com` domain; the field is Disabled with the logic note; Save still works for name and phone.
17. **Edit profile with no changes** → Save disabled [P15]; pressing back simply pops.
18. **Phone changed** → the "Verified" pill still shows (logic: it only checks presence) [P26].
19. **Sign out with an active session** → guard sequence 08.10–08.15 (logic). If the end call keeps failing, "Cancel Logout" always returns to a working, charging state.
20. **Sign out offline** → "Logout failed: …" toast; the user stays signed in.
21. **Delete account offline / failure** → toast (08.22); the account stays; no partial sign-out.
22. **Host switch failure** → thumb snaps back + toast [P10]; no host role → registration (out of scope).
23. **Notifications: many unread** → badge caps at "9+" (same rule as the Messages tab); the list itself is unbounded with pull-to-refresh.
24. **Notification for a deleted booking or chat** → the row still marks read; navigation lands on `/my-bookings` (07.40; the list simply doesn't contain it). Default chosen; flag.
25. **Host-type notifications** on a driver account → shown with the Booking tile and routed by the logic (host screens); not drawn.
26. **Mark all read with zero unread** → the button is hidden (logic).
27. **Profile while charging** (08.03) → accessory above the tab bar; scroll inset +60; toasts at y 660.
28. **Dynamic Type (AX sizes)** → header card stacks (avatar above name), stat tiles become 3 rows (label left, value right); List Rows grow in height; Vehicle Card wraps the pill below the name; sheets become scrollable with buttons pinned; Notification Row time moves under the body.
29. **VoiceOver order (Profile)** → Profile heading · header card (one element) · stats (one element) · mode switcher · rows top → bottom · Sign out · version · tab bar.
30. **Reduce Motion / Reduce Transparency** → §2.3 fallbacks; the Mesh avatar stays (static paint).
31. **Small phones (iPhone SE)** → not drawn; rules: header card avatar 56, stats Display/S, sheets scroll above 600pt height.
32. **Dark mode** → not drawn tonight; all fills are tokens.
33. **Repeated taps on alert buttons** → the first tap dismisses the alert and starts the action; a second tap lands on nothing (alert gone) or on the HUD (blocks touches). The vehicle card being deleted ignores taps while dimmed.
34. **Time-ago text past midnight** → rows move from TODAY to YESTERDAY on the next refresh / app-resume, not live (logic refetch points).

## 1. Overview

**Goal.** Messages is the quiet back-channel between a driver and a charger host. It answers two questions in one glance: "Did my host say anything I need before I arrive?" and "How do I reach them right now?". Every thread is anchored to the booking it is about, so the gate code, the parking bay and "Charging now" all sit next to the conversation. The flow is lower priority than charging, so it reuses the app's language as-is: Quiet mesh, Frost Strong groups, glass chrome, emerald for "mine", and light SF Pro type (titles Medium, body Regular, Emph styles Medium; no Bold or Semibold anywhere). This flow has no price, %, kWh or cost of its own, so it uses no Display styles. The only live numbers are inside the reused Live Charging accessory. The host's phone number stays inside the real body sentence of the call sheet; it is not lifted into a Display number.

**What the logic gives us (unchanged):**
- **Inbox:** "Messages" header with a bell (red dot) → Notifications; four filter pills with counts (All · Unread · Inquiries · Upcoming); thread rows (initials avatar, name, preview or "No messages yet", booking chip, "New inquiry" chip, relative time, unread dot, active-session marker); loading, error, empty, filtered-empty, pull to refresh. Tap → thread on root (tab bar hidden).
- **Thread:** three entry points (inbox row, booking sheet by `bookingId`, push by `chatRoomId`) with their own loading/error; title = participant name, tap → Conversation options; phone → Call sheet (hidden when blocked); presence "typing…" / "Online"; booking banner (confirmed → "Upcoming booking", paused → "Charging now") → read-only booking details; date separators; mine/theirs bubbles with "h:mm AM"; four system event cards; three empty heroes; **five composer modes** (the unlock rules, §1.5); inquiry template sheet; send errors.
- **Conversation options:** "Conversation options", trust chip, "Block {name}" and "Report conversation" both disabled "Coming soon", Close.
- **Call sheet:** "Call {name}", with-number and no-number bodies, Call (disabled without a number) → `tel:`, dialer failure, Cancel.

**What the design adds (flagged):** station context on rows and banner [MS1, MS10]; a Live "Charging now" row that matches the rest of the app instead of the code's amber border [MS2]; presence inside a glass title capsule [MS7]; typing bubble [MS8]; optimistic sending with a retryable failed bubble [MS9]; choose-then-send inquiry sheet with a 140 counter [MS11]; native long-press Copy [MS12]; a jump-to-latest pill [MS13]; "Find a charger" that actually goes Home [MS4]; an identity row in Conversation options [MS22]; typing-timing defaults [MS23]; live-update assumptions that Rayan must confirm [MS24]; an avatar only beside the last bubble in a run [MS25]. Where a proposal replaces visible logic behaviour, the logic version is drawn too (09.13b, the logic's spinner on Send), the same way 07.40 keeps the logic frame.

## 4. Micro-interactions

### 4.0 Tokens, shared rules and additions (for 00-system)

**Row format (the brief's micro-interactions card).** Every row below reads: **Trigger** → response · timing · haptic · VoiceOver (VO) · Reduce Motion (RM). Copy it onto the canvas cards in this form, e.g. "3  Press a row → highlight, push thread · 0 ms on / 150 ms off, push ≈ 350 ms `smooth` · none · 'Bilal. Unread…' · cross-fade push".

**New tokens (this flow):**
- `typing`: three 7pt dots (icon/tertiary) in a theirs-style bubble. Each dot loops opacity 0.35 → 1 → 0.35 and y 0 → −2 → 0 over 1.2 s ease-in-out, staggered 160 ms. RM and Low Power Mode: static dots at 60%; the capsule's "typing…" label does the work.
- `send`: the outgoing text flies from the composer field to its bubble slot (matched geometry, `smooth`, 320–400 ms by distance); the corner radius morphs from the field's 22 to the bubble's 20 with the tail. Pending opacity 0.6. RM: the bubble fades in at its slot (`fade.quick`), no flight.

**Reused tokens:** `snappy` (≈ 300 ms), `smooth` (≈ 450 ms), `bouncy` (≈ 400 ms, one 4% overshoot), `fade.quick` (150 ms ease-out), `fade.std` (220 ms ease-out) from 02 §4.0; `roll` (220 ms digit roll; RM 150 ms cross-fade) from 00-system §2.1; `pulse` (ring around the live dot, scale 1 → 2.2, opacity 0.5 → 0, 1.33 s loop; off in RM and Low Power Mode) from 06 §4.0.

**Press feedback (02 §4.0, applies to every row below, so rows only restate it when it differs):** `Button / Large` → Pressed variant + scale 0.97 (`snappy`); glass `Icon Button` (back, bell, phone) → scale 0.92 + fill brightens 6% (`snappy`); cards, the Booking Banner and System Event Cards → scale 0.98 (`snappy`); chips, pills and the Chat Title capsule → scale 0.96 (`snappy`); a drag of more than 10pt cancels a press. Disabled controls have no press state and no haptic. RM: no scale; the pressed element dims to 85% for the touch.

**Haptics (app map from 02 §4.0 / 08, applied here):** selection = filter pills, template choice · light = bell, title capsule, phone, banner, system cards, "Find a charger", "Show all", Retry, the pull-to-refresh threshold, the "New message" pill, retrying a failed bubble, opening a sheet from a button · medium = inquiry / follow-up **Send** (a commit) · success = not used (sent messages stay silent) · warning = the conversation becomes blocked while open; the 140-character cap · error = any failure (send, inquiry, open, load, booking details, dialer, failed Retry). **Free-text send has no haptic** (frequent action; iOS Messages convention). Haptics fire on release, never on touch-down; never two within 300 ms (08 rule).

**Toasts (02 §4.0 Toast rules):** enter from 12pt below with opacity 0 → 1 (`smooth`), leave by reversing (`fade.quick`); stay 4 s for one line without an action and 6 s for two lines; swipe down dismisses; one at a time. Haptic follows the tone (Error → error). VO: polite announcement without moving focus; the timer pauses while VO focus is inside the toast. RM: fade only.

**VoiceOver announcements (06 §4.0 rule):** all announcements are polite (`UIAccessibility.post(.announcement)` / Flutter `SemanticsService.announce`), never more than one every 10 s except errors. Screen titles and sheet titles carry the heading trait. All VO strings in this section are new accessibility labels, not visible copy.

1. **Thread scope.** Threads are drawn per host–driver pair (the logic resolves a pair thread from a booking; system cards carry the station, which only makes sense with several bookings per thread). If the server turns out to be per booking, nothing in the components changes; only the dummy history does.
2. **`inquiry_pending`** is counted by the Inquiries filter but is not in the composer table. **Default:** draw it as waitingForHost (no follow-up timer). One question for Rayan in the FLAG card.
3. **Empty-thread frames are state demos.** 09.17 and 09.22 show T2 and T3 before their first message. In the dummy history (07) those hosts have older bookings (Usman: completed 2 Oct, host-cancelled 29 Sep; Johar Town: completed 13 Sep, cancelled 14 Sep); the canvas notes say "state demo".
4. **Hero precedence** (logic order): upcoming booking → not yet unlocked → neutral. A cold thread with an upcoming booking shows the booking hero **and** the Template composer. That combination is correct, if unusual.
5. **Unread counts.** Tab badge = unread **messages** ("9+" cap, hidden at 0); Unread pill count = **threads** with unread messages. Both are logic. They can differ ("2" vs "1"), which is fine.
6. **Thread with both a booking chip and "New inquiry":** both pills, booking first; the station line truncates first, then disappears if there is no room.
7. **Several upcoming bookings with one host:** the chip and banner show the soonest (confirmed or paused).
8. **Active session row** (09.04): Live pill replaces the booking chip; the row keeps its position by last activity (not pinned) so the list doesn't jump.
9. **No timestamp on a thread with no messages:** the time is hidden and the preview reads "No messages yet" (text/secondary).
10. **Long names / station names:** row name 1 line; capsule name truncates at 230 max width; station truncates. Full strings stay in VoiceOver labels.
11. **Push while the same thread is open:** no banner (logic), the bubble animates in (§4.4-8). Push while another thread is open: banner shows; tapping it replaces the current thread (no stacking of threads) [MS24 (e)].
12. **Opening a thread from a booking whose thread doesn't exist yet:** 09.18 → the server creates/resolves it; failure → 09.19 with Retry.
13. **Free-text limits:** the logic has none. **Default:** no counter; the field scrolls past 5 lines. Whitespace-only text can't be sent.
14. **Typing events:** emitted at most every 3 s; the host typing bubble times out after 6 s without an event [MS23].
15. **Offline send:** fails → 09.14. We don't queue messages for later (no logic for it).
16. **Host blocks while the driver is typing:** the draft is discarded, the keyboard dismisses, and the composer becomes the Blocked notice (§4.5-5).
17. **Follow-up timer** is computed from the server's last-nudge time. If the device clock is wrong, the server wins: a rejected follow-up shows the inquiry failure toast.
18. **Booking banner fetch error** (on tap): Toast Error "Unable to load booking details." (real); the banner stays (09.15b). The same applies to a tappable system card.
19. **Booking ends while the thread is open:** the banner collapses (only confirmed/paused show it, logic); a "Charging session completed" card arrives when the server posts it.
20. **No phone number:** the phone button still shows (logic hides it only when blocked) and opens the No number sheet (09.31).
21. **The iOS call prompt** (OS-owned) appears after "Call" whenever iOS shows it for `tel:` links; it is not drawn ([MS16]).
22. **Urdu / RTL messages:** bubble text follows its own direction (natural alignment inside the bubble); bubble side stays by sender. Roman Urdu needs nothing special.
23. **Dynamic Type (largest):** rows grow (the meta row wraps under the preview), bubbles grow to 85% width, the capsule hides presence text and keeps the dot, the composer grows; pills scroll horizontally.
24. **Reduce Transparency:** capsule, banner, separators, cards and composer become Surface + hairline (02 rule). **Reduce Motion:** every flight, morph and shake → `fade.quick`; typing dots static; no `pulse`, no `roll` (150 ms cross-fade); presses dim to 85% instead of scaling. **Low Power Mode:** `typing` and `pulse` loops stop (static), as 06 §4.0.
25. **Time zone:** Asia/Karachi. "Today"/"Yesterday" flip at local midnight on the next minute tick; relative times in the inbox update each minute while visible.
26. **Debug / host-only items:** in-app WebRTC `CallScreen` and `IncomingCallListener` are dormant for v1 (Appendix 2) and are not drawn.
27. **T3 (Sana) vs 07's history.** 07 has Ayesha completing a Johar Town session on 13 Sep, yet T3 is still in `inquiry_waiting`. Default story: Sana never replied in chat, so the thread was never unlocked; the booking alone doesn't unlock it (the logic ties `unlocked` to the relationship, not to bookings). Her trust chip would read "1 completed booking together". **Rayan: does a completed booking unlock free text?** If yes, T3 needs a host with no past bookings; only the dummy data changes.
28. **Avatar size.** Bubble and typing avatars use `Avatar` S 32 (04 §6), the component's smallest size, so no XS variant is added; theirs bubbles start at x 56.
29. **Bottom-edge rule.** Every composer mode, sheet button stack and the "Send" button ends at y 824 (16 above the home indicator, brief). With the keyboard up, the composer sits 8 above the keyboard.
